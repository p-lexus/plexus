01What shipped

Protocol conformance done

Four gaps between PROTOCOL.md and the implementation.

  • requestedBy is enforced. Missing owner is rejected with a published error rather than silently routed to public, where the sender's own subscription would never have seen it.
  • Result shape and retention are guaranteed by the bridge, not by the executor remembering. A forgotten retain: true used to mean late subscribers saw nothing.
  • Cancel is terminal. A retained cancelled result is published and later executor output suppressed, so listeners are never left hanging.
  • The v1.0 compatibility layer is gone — and with it the last hardcoded capability. The bridge no longer contains the string code.review.

Durability done

The client id no longer contains the process id. That single change is what makes clean: false mean anything: with a changing id, every restart was a new session, the broker's queued messages stayed orphaned with the dead one, and any job published while the gateway was down was lost silently.

Collisions now self-heal — detected at 5+ connects in 60s, resolved by taking a distinct id, and reported as degraded durability rather than left looking like flaky networking.

Console done

Rebuilt as an operator console: severity stripes, per-job milestone timelines, filtering, copyable topics, light and dark. Job records now keep their event history — previously only the most recent survived, which discarded exactly what explains a job's behaviour.

Deployment variables are managed from the console, stored 0600 outside openclaw.json, write-only over the API, and gated behind a required token.

Structure and tests done

One 1412-line file became 15 focused modules. The point was not tidiness — it was that 27 unit tests now cover code that previously could not be tested without a broker: the owner-scoped-only topic invariant, forced retention, the env-before-args ordering that stops an argument smuggling ${SECRET}, variable precedence, 0600 permissions, both auth levels, CSRF, and that the client id is stable and pid-independent.

Documentation, reproducible screenshots, CONTRIBUTING and CI are in place.

02Bugs found — including mine

Reconnect on every job caused by me

register() runs once per agent session, not once per process. Dispatching a job re-registers the plugin, and my reload-takeover could not tell that from a rebuild — so it tore down the MQTT client and reconnected on every job. I replaced a harmless no-op with a reconnect while fixing something else.

Jobs re-dispatched and duplicated

The dispatch prompt still told the executor to spawn a nested subagent — correct under the old design, wrong once dispatch delivered straight into an isolated session. The outer run settled in seconds while the real work continued elsewhere, the watchdog read that as "finished without a result," and re-ran the job.

Console stuck on "Checking…"

A view function had been deleted by an over-wide edit. render() names every view in one object literal, so a missing one is a ReferenceError on every render. It survived because I was verifying the console by fetching the HTML and grepping it — which proves the file is served but never runs a line of it. That is now a test.

Unbounded fetch loop on the Variables tab

render() called loadSecrets(), which called render(). Opening the tab hammered the endpoint for as long as it was open. Found because the screenshot of that view never terminated.

Two things that were never mine

A spike to 47 reconnects was DNS failure resolving your broker's ELB — a network or VPN drop. The mesh rode it out and recovered without losing its session, which is exactly what the durable design is for.

Separately: your gateway log captures only info-level plugin output. Every warn and error is dropped, so absence of an error line proves nothing. Operational alerts now emit at error level and mirror to info to get around it.

03The main recommendation

v1.3 — delegation. This is the one that matters.

Your model is that each agent owns distinct capabilities, and an agent that hits work outside its own asks whoever is better at it. A human enters at one agent; after that, work flows agent to agent. Two things block that today.

Agents cannot see each other

Each agent subscribes only to its own command topics. None subscribe to registry/+/profile. Every agent publishes a capability catalog that nobody reads — so no agent knows what any other can do.

Asking is one-way

An agent can publish a job to another agent, but its own run ends before any answer arrives. It can notify a peer; it cannot ask one. So delegation is a dead end — the asking agent can never use what came back.

With both fixed, this works, and each hop is its own job:

              dba → security   policy check   job job-9f21
      conan folds it into one answer → you

Decided: the asking agent waits. You said the entry agent should return one complete answer, and conan asks for help precisely because it needs that answer to finish its own work. The cost is a held-open session, which is what the hop limit and maxJobDurationMs bound.

04Before a second agent exists

Both break immediately with two agents on one machine.

  • Panel port. Every agent defaults to 8765. The second fails to bind and its console silently never appears. Each agent needs its own web.port.
  • Client id. Derived from hostname + install path, so separate directories are fine. Copy a configured agent to make a second one and both share an id and kick each other off the broker. Set broker.clientId explicitly per agent.

05Before open-sourcing

The git history is not clean blocker

The working tree is clean and verified. The history is not: commits before the genericisation still contain internal topic roots, an internal repository name, and Slack user ids. Those stay readable in a public repo.

Cleanest fix is to squash to a single initial commit before flipping to public. The history lost is mostly this session's debugging, not anything worth preserving.

  • No license. Currently all-rights-reserved, which means nobody may legally use or contribute. Apache 2.0 is the usual choice for a protocol — permissive, with a patent grant that MIT lacks. Relicensing after outside contributions requires their agreement, so decide before accepting any.
  • Naming. Three names in play: plugin id mqtt-bridge, package agent-mesh-bridge, repo agent-mesh-protocol. The id is load-bearing — it is the config key and the URL prefix — so it was frozen deliberately while fixing live bugs. Worth aligning, in one restart, before strangers read it.

07Suggested order

1
Peer discovery + mesh_ask

The mesh does not exist without these. Everything else in v1.3 is support.

2
Lineage, hop limit, cancel propagation

Ship alongside delegation. Retrofitting lineage after chains exist means debugging blind.

3
Stand up a second agent

Distinct port and client id. Proves the model with two real specialists rather than one.

4
Squash history, pick a license, align naming

The gate to going public. Independent of the protocol work.

5
Move Slack ids to the local store; clear stale retained topics; raise the log level

Housekeeping, worth doing while it is quiet.
